# 科研 PDF 精确解析（回答问题，也给出依据）

## 目标

把一份科研 PDF 变成**可复核的结构化结果**：每个结论都能指回原文的页码与区块，读不出的地方如实标注，而不是靠猜补齐。评审会逐项核对"提得全、排得对、拆得清、核得回"四个要求。

## 输入与输出契约

- 输入：`/input/case.json`（任务说明、材料路径、待完成问题、输出字段）与 `task.md`（题面）。
- 工作目录：`/app/work`（放中间文件）；最终结果写到 `/app/output`。
- 必须产出 `/app/output/result.json`，包含 `case_id` 与题面要求的全部 `output_contract` 字段。
- 先读 `case.json` 和 `task.md`，确认"要提取什么、以什么格式输出"，再动手；不要凭文件名或领域标签猜测内容。

`result.json` 统一骨架（在此基础上补齐题面字段）：

```json
{
  "case_id": "<来自 case.json>",
  "status": "success | partial | unknown | refused",
  "result": { "<题面要求的答案/结构化字段>" },
  "evidence": [
    {"page": 3, "block": "左栏第2段", "quote": "原文片段", "field": "对应 result 的哪个字段"}
  ],
  "uncertainty": ["列出的未报告/无法判断/材料冲突项"],
  "change_log": ["本次相对上一版的修改记录，可为空数组"]
}
```

## 四条硬性要求（逐条自检）

1. **提得全**：正文、图表题注、脚注、参考文献逐字提取；不漏行、不丢段；页眉页脚与正文分离，不混入正文。
2. **排得对**：双栏/多栏按原版面顺序输出；不串栏、不错行；不把相邻段落拼成一句；跨页段落正确续接。
3. **拆得清**：章节层级、表格行列与单元格归属、公式上下标与希腊字母还原成可继续处理的结构。
4. **核得回**：每段文字、每张表格、每个关键结论都能指回原文页码与区块；读不出的部分如实标注。

## 标准工作流

1. **定位与盘点**：用文本工具取 PDF 页数与是否有文本层。若大部分页面无文本层，走扫描件 OCR 流程。
2. **版面分析**：用渲染工具看第 1–3 页的实际版面，判断单栏/双栏/多栏、是否有跨页表格、页眉页脚样式。
3. **结构化提取**：优先跑 `python3 scripts/pdf_extract.py <pdf> result.json --markdown`（脚本用 `pdftotext -bbox` 逐词坐标做栏检测、阅读顺序、表格候选、上下标启发式，无 Python PDF 库依赖；无文本层自动转 `pdftoppm + tesseract` OCR）。脚本不可用时，用 pdf-text-tool 逐页取文本并人工核对栏序。
4. **表格**：对每张表输出 Markdown 或 HTML，保留跨行跨列、合并单元格与多层表头；跨页续表合并为一张并注明"续表"。
5. **公式**：保留 LaTeX 形式与编号，上下标、希腊字母、正斜体不丢；无法确认的符号标 `[不确定]`。
6. **逐块核对**：提取后抽样比对原文渲染图，确认栏序、段落边界与表格结构正确。
7. **回填定位**：为每个结果字段补 `page`/`block`/`quote` 证据；写 `uncertainty` 列出所有未报告、无法判断、材料冲突项。
8. **落盘**：先写中间结果到 `/app/work`，确认无误后写 `/app/output/result.json`，并写 `/app/output/README.md` 简述方法与限制。

## 多栏与阅读顺序

- 先识别版心与栏分割线：双栏论文以页面中线为界，三栏按三分点；但图注、通栏表格、页眉页脚可能跨栏。
- 阅读顺序按"左上→右上→左下→右下"（先整栏再下一栏），不要按 PDF 内部字符流的顺序直接拼接。
- 页眉页脚（页码、期刊名、DOI、作者缩写）单独标出，不进正文；正文中的脚注与参考文献分别归类。
- 跨页段落：段落末行无句末标点或表格被截断时，检查下一页开头是否属于同一逻辑单元，正确续接。

## 表格解析

- 先渲染表格区域为图片再识别，避免直接拼文本流导致行列错位。
- 用网格线、行高聚类与表头关键词（单位、指标名）判定表头行数；合并单元格用 `rowspan`/`colspan` 标注。
- 输出 Markdown 表格；跨行跨列无法用 Markdown 表达时改用 HTML 表格，并在旁注明原始行列结构。
- 跨页续表：合并为一张表，注明"表 X（续）"，不重复计算表头。

## 公式与特殊字符

- 公式输出 LaTeX 原文 + 公式编号；正文引用编号保持一致。
- 上下标、希腊字母（α β γ Δ Σ 等）、矢量/粗体、正斜体如实保留；渲染图片与文本层不一致时以渲染图为准并注明。
- 数学符号（如 ∑、∫、∂）在文本层常被映射错（例如 ∑ 被提取为 P）；对公式区域必须用 `pdftoppm` 渲染后与文本层比对，以渲染图为准并注明差异。
- 单位与变量：区分正体单位（如 m、s、mol）与斜体变量（如 x、t），不混用。

## 扫描版与 OCR

- 无文本层或文本层为乱码时，用 ocr-tool 分页识别；先做图像预处理（去噪、二值化、倾斜校正）。
- OCR 结果必须与渲染图抽查比对；数字、单位、上下标、希腊字母是高频错点，逐处核验。
- OCR 置信度低或无法辨认的字符，写成占位符并列入 `uncertainty`，不猜填。

## 诚实与不确定性规则

- "未报告"与"无法判断"分开写：前者是材料里没有，后者是材料里有但读不出/冲突。
- 关键结论必须能回到原文页码与区块；不能回溯的推断标为 `[推断]`，不得写成事实。
- 材料缺失、运行失败、乱码、加密 PDF 等异常，写明原因与可人工接管的位置。
- 宁可标注"读不出"，不要补造内容。

## 输出自检清单（落盘前逐项过）

- [ ] `result.json` 含 `case_id` 与题面全部 `output_contract` 字段。
- [ ] 每个关键字段都有 `evidence` 定位（page/block/quote）。
- [ ] `uncertainty` 覆盖所有未报告、无法判断、冲突项。
- [ ] 表格行列归属、公式上下标、多栏顺序已抽查无误。
- [ ] 页眉页脚未混入正文；参考文献、脚注、图注分类清晰。
- [ ] `status` 如实反映完成度（partial/unknown 要说明原因）。
