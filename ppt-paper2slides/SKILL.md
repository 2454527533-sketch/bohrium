# 论文转学术 PPT（组织页面，也保留证据映射）

## 目标与三条判对标准

把一篇连续叙述的论文改写成**页级离散、可讲、可核验、可编辑**的学术 PPT。判断是否做对，只看三件事：

1. **主线对**：页面叙事与论文自身贡献一致（问题→方法→证据→结论），而不是按段落顺序搬运。
2. **核得回**：每一页内容都能回溯到论文中的图、表、章节或数据，引用编号与正文一致。
3. **能用**：成品在指定模板与软件版本中能打开、播放、编辑，并能由他人按记录复跑出同一版式。

## 输入与输出契约

- 输入：`/input/case.json`（任务说明、论文/材料路径、模板路径、受众、时长、页数上限、输出字段）与 `task.md`；`environment/resources.yaml` 列出可用工具与预装软件。
- 工作目录 `/app/work`（放中间产物：抽取的图、中间 JSON）；最终结果与可编辑产物放 `/app/output`。
- 必须产出 `/app/output/result.json`，含 `case_id` 与题面全部 `output_contract` 字段。

`result.json` 统一骨架（补齐题面字段）：

```json
{
  "case_id": "<来自 case.json>",
  "status": "success | partial | unknown | refused",
  "result": {
    "main_line": {"problem": "", "method": "", "evidence": "", "conclusion": ""},
    "slide_plan": [{"page": 1, "claim": "", "key_points": [], "figures": []}],
    "deck_file": "outputs/slides.pptx",
    "preview_files": ["outputs/slides.pdf"],
    "evidence_map_file": "outputs/evidence_map.json"
  },
  "evidence": [
    {"slide": 3, "paper_page": 6, "kind": "figure", "ref": "Fig 4", "quote": "原文片段"}
  ],
  "uncertainty": ["列出的未报告/无法判断/材料冲突项"],
  "change_log": ["本次相对上一版的修改记录"]
}
```

## 六步工作流

1. **读材料与边界**：先读 `case.json` 与 `task.md`，确认论文路径、模板路径、受众、时长、页数上限、是否给起始 deck。再打开模板（`office-renderer` 渲染或 python-pptx 读 layout）确认版式、占位符、配色、页脚规则。不要凭文件名或领域标签猜测内容。
2. **主线提取**：从论文提取「要解决的问题、核心做法、关键证据、结论与限制」形成叙事骨架；区分主结论与支撑细节，明确哪些图/表是主证据。
3. **页结构设计**：按主线把内容映射成页——一页一个主张；长段落改写为可讲述的短语；控制单页信息密度（一般 3–5 个要点）；先写 `slide_plan` 与 `evidence_map` 再生成文件。
4. **证据映射**：为每页定位论文中的图/表/公式/数据来源，保留编号、单位、图注和必要条件；引用编号与正文严格一致，防止张冠李戴、示意图当实验数据、他人结果当本文结果。
5. **生成可编辑 PPTX**：用 `scripts/build_pptx.py` 从 `slide_plan` 与模板生成 `slides.pptx`；复用模板 master/layout 与主题，不覆盖模板的标题/页脚/配色；给每页写讲稿备注。
6. **导出与校验**：用 `office-renderer` 导出 PDF/PNG 预览；逐页检查溢出、字号过小、字体替换、图表错位、编号错位；发现问题回到第 3–5 步修正。最后写 `result.json` 与 `README`（记录版本、依赖、字体与复跑步骤）。

## 模板约束与版面适配（关键）

- 优先使用模板中已有的 layout（标题页/章节页/内容页/图表页/空白页），在占位符内排布，不覆盖模板主题色与页脚。
- 长标题截短为页级主张句，正文用 3–5 级短句；单页文字不超过约 6 行要点。
- 多图并列用模板的图表 layout 或两栏；大表格改用「表头 + 关键行」或拆分，不靠缩小字号硬塞。
- 字体优先用模板声明的字体；发现缺字时用 `font-discovery` 找可用替代，并记录替换。

## 讲稿备注规则

- 备注是「补充」不是「复读」：写过渡句、强调点、被提问时的补充证据、与下一页的衔接。
- 每页备注 2–4 句；给数字/图表写一句「如何读这张图」。
- 备注不出现页面正文没有的来源与数字。

## 证据与诚实规则

- 每页的关键主张都要能回到论文页码/章节/图表；`evidence_map.json` 按页记录 `{slide, paper_page, kind, ref, quote}`。
- "未报告"与"无法判断"分开写：前者是论文没有，后者是读不出/冲突。
- 图表提取失败、公式是图片、PDF 加密、页数超限、模板占位符不足等异常，写明原因与可人工接管位置，不补造。
- 不生成论文里不存在的数据/图/结论；引用他人结果时标明来源。

## 输出自检清单（落盘前逐项过）

- [ ] 主线与论文贡献一致，页序可讲，页数未超上限。
- [ ] 每页一个主张，要点短语化，无段落直接粘贴。
- [ ] 每页证据映射齐全，图表编号/单位与正文一致。
- [ ] 讲稿备注与页面互补，不重复页面文字。
- [ ] `slides.pptx` 可打开、可逐页编辑；PDF/PNG 预览已导出且版面无崩坏。
- [ ] `result.json` 含 `case_id` 与题面全部字段，`status`/`uncertainty` 如实。
- [ ] 版本记录（模板、字体、软件版本、复跑命令）齐全。
